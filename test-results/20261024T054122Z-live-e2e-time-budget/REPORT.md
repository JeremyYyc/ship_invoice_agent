# 60 秒 LLM 超时预算实验报告

## 结论

该配置验证了应用层重试边界和超时降级机制，但不适合作为当前
`qwen3.8-27b` 的最终配置。

- 单次超时：60 秒
- 每份 `RawDocument` 总预算：130 秒
- 应用层重试：1 次
- Provider SDK 内部重试：0 次
- 总耗时：765.21 秒（约 12 分 45 秒）
- 优化前总耗时：1298.98 秒（约 21 分 39 秒）
- 耗时下降：约 41.1%

## 结果

- 4/4 场景完成，超时没有中断后续附件。
- 11 次模型调用超时。
- 7 份文档中只有 2 份完成结构化抽取。
- PDF2 charge recall、金额、币种和 reference accuracy 均从 1.0 降为 0.0。
- 所有超时文档均安全输出 `PENDING_REVIEW`，没有自动入账。

## 判定

机制通过，参数失败。60 秒低于本轮模型处理正常复杂账单所需的约
93–110 秒，导致可接受请求被提前终止。因此最终候选参数调整为：

- 单次超时：115 秒
- 每份文档总预算：235 秒
- 应用层重试：1 次

该设置覆盖优化前正常成功请求的实测上界，同时将单文档最坏等待时间从
原先三次 120 秒请求压缩为最多两次 115 秒请求。
